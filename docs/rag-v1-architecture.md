# NJFU Wiki RAG v1

## 目标

RAG v1 在现有“用户画像 + 双知识库检索”之后增加受约束的大模型生成层。模型不自行搜索 GitHub 或互联网，只能使用本轮传入的政策条目和资料目录条目。

## 处理链路

1. 从当前输入和历史画像中抽取年级、目标、基础、时间和组队情况。
2. 信息不足时使用确定性追问，避免模型反复询问已经提供的字段。
3. 信息充足或属于事实查询时，分别检索竞赛政策库和资料目录库。
4. 将用户画像、规则基线建议和带编号的检索条目交给大模型。
5. 模型返回结构化 JSON，服务端校验并与基线结果合并。
6. 前端展示回答、行动步骤和 P1/R1 形式的证据编号。
7. 模型不可用、超时或返回异常时自动回退到规则基线。

## 大模型配置

服务端兼容 OpenAI Chat Completions 风格的接口，使用以下环境变量：

- `LLM_API_BASE_URL`：服务地址，可以填写到 `/v1` 或完整 `/chat/completions`。
- `LLM_API_KEY`：服务端密钥，不得提交到仓库或放入浏览器代码。
- `LLM_MODEL`：模型名称。

本地开发可以使用本地兼容服务；已发布的云端站点必须配置云端可访问的模型接口。本地 `localhost` 模型不能被云端站点直接访问。

## 生成约束

- 事实性建议使用 `[P1]`、`[R1]` 等编号引用本轮证据。
- 不允许编造比赛、分值、报名时间、老师联系方式、资料或链接。
- 涉及综测和推免时必须区分历史口径与当届正式细则。
- 当前知识库依据不足时明确说明，不使用模型常识补齐政策事实。

## 评测

- `pnpm eval:baseline`：画像和检索基线。
- `pnpm eval:badcases`：已修复 bad case 回归。
- `pnpm eval:generation`：对已启动且已配置模型的站点运行生成层评测。

生成层自动检查引用覆盖、引用编号、行动结构、风险表达和禁止内容。忠实度、相关性、推荐适配性与行动质量按 `evals/generation-rubric.md` 人工复核，或者使用与被测模型不同的裁判模型评分。
